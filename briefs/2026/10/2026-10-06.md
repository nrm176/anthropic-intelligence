# Anthropic Intelligence Brief — 2026-10-06

## エグゼクティブサマリー
前回（10月3日）以降の実質的な差分は二つです。第一に、Claude Code v2.1.290で **Managed Agents、組織ポリシーを認識するplugin hooks、運用診断** が強化され、Claude Codeが個人向けcoding agentから企業管理可能なagent runtimeへさらに近づきました。第二に、Claudeの **India in-country inference** がAmazon Bedrock経由で開始され、規制産業向けのdata residency選択肢が増えました。

## 1. 何が変わったか

### Claude Code v2.1.290
**事実:** Anthropicは10月6日（JST）にClaude Code v2.1.290を公開しました。plugin/mod向けに、subagentを識別する `agentId`、組織が要求するapproval levelを示す `ceiling`、server-side tool useの観測情報が追加されました。また `claude plugin validate` がgating hookの検証情報を出力し、Managed Agentsのquickstartを `/claude-api managed-agents-onboard` から構築できるようになりました。managed settingsが管理対象外ファイルへのsymlinkになっている場合の警告や、sandbox設定がmanaged policyで無効化されている場合の診断も追加されています。

**分析:** 重要なのは個々のCLI機能ではなく、Agentのpermission decisionを「モデル/ユーザー」だけでなく **organization policy → hook → subagent → tool** の階層で扱えるようになっている点です。大規模なClaude Code導入では、これが中央統制と開発者自律性を両立する基盤になります。

### India in-country inference
**事実:** 10月5日、Claude Opus 5、Sonnet 5、Haiku 4.5についてAmazon Bedrock経由のIndia in-country inferenceが開始されたと複数の報道がAnthropicの発表を引用して伝えています。India endpointのrequestは国内で処理され、規制産業・政府向けのdata residency要件を支援します。

**分析:** モデル性能ではなくdeployment topologyが競争軸になっています。金融・公共などでは「どのモデルか」より「どこで推論され、誰がidentity/audit/access controlを管理するか」がproduction移行の条件になるためです。

## 2. なぜ重要か
Claude Codeの最新変更からは、企業向けagent architectureが **Identity → Organization Policy → Agent/Subagent → Tool/MCP → Sandbox → Audit** に収束していることが読み取れます。特にsubagentごとのpermission checkをhookが識別できることは、multi-agent化で権限が暗黙に継承される問題への実務的な対策になります。

## 3. 具体的なユースケース
- 開発部門で、main agentにはread/writeを許可し、deploymentを行うsubagentだけ追加approvalを要求する。
- Managed Agents quickstartをIaC的に展開し、deep researchなどの標準agentを部署横断で再利用する。
- Indiaの金融・公共ワークロードで、Bedrockの国内推論とIAM/auditを組み合わせてClaudeをproduction利用する。

## 4. 技術的な示唆・統合パターン
推奨パターンは **SSO/IAM → managed settings → Claude Code/Agent SDK → policy-aware hooks → MCP/tools → sandbox → centralized logs** です。plugin/modは強力ですが、組織ポリシーを迂回できない設計を前提にし、hook自体もコードレビュー・署名・配布管理の対象にすべきです。

## 5. 見落とされがちだが有用な機能

### `ceiling` + `agentId` in tool.check
**何か:** plugin hookが「どのsubagentのtool requestか」と「組織が要求するapproval上限」を認識できます。
**なぜ見落とされやすいか:** モデル更新ではなくClaude Code release note内のhook API変更だからです。
**解決する問題:** multi-agent環境で、main agentとsubagentのpermissionを同一視してしまう問題を減らします。
**誰に有用か:** Platform Engineering、Security、AI CoE、Claude Code管理者。
**利用例:** production deploy toolだけはsubagentから呼ばれた場合にhuman approvalを必須化する。

### managed settings診断
**何か:** managed settingsが外部ファイルへのsymlinkになっている場合や、ユーザー設定のsandbox allowRead / allowed domainsが組織設定で無効になっている場合に警告します。
**なぜ見落とされやすいか:** `/status` / doctorの運用品質改善としてリリースされているためです。
**解決する問題:** 「設定したはずなのに効かない」状態と、managed policyの意図しない迂回を発見しやすくします。
**誰に有用か:** Enterprise endpoint管理者、Security、Developer Experience。
**利用例:** 数百台へClaude Codeを展開する前にdoctorをCI/端末チェックへ組み込み、policy driftを検出する。
