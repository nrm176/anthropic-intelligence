# Anthropic Intelligence Brief — 2026-10-08

**対象期間:** 2026-10-07〜2026-10-08（JST）。前回（10月7日）のCyber Verification ProgramとClaude Code v2.1.291は重複のため除外。**[一次情報]** は公式発表に基づく事実、**[分析]** は導入上の示唆。

## 1. 何が変わったか

1. **Claude Haiku 5.5を10月7日公開 [一次情報]** — モデルIDは `claude-haiku-5-5`。1M token context、128K token最大出力、adaptive thinking/effortをサポート。Claude API、Amazon Bedrock、Google Cloud、Microsoft Foundry等で提供。高頻度の分類・抽出・要約・サブエージェント向け。**100K tokens以下の入力では**入力$0.10/MTok・出力$0.50/MTok、100K超では$0.50/$2.50。AnthropicはHaiku 4.5比で平均約75%の実行コスト削減と説明。出典: https://www.anthropic.com/claude-haiku-5-5 / https://platform.claude.com/docs/en/models/haiku-5-5/overview
2. **Claude Sonnet 5.5のcache read単価を半額に [一次情報]** — 10月7日から$0.20→$0.10/MTok（base inputの0.05倍）。cache writeや通常入出力単価は据え置き。Anthropicは一般的なagentic workで約20%のコスト削減と説明。出典: https://platform.claude.com/docs/en/release-notes/overview
3. **Google Docs/Sheets/Slidesへの直接編集（beta） [一次情報]** — Claude for Google WorkspaceがPro/Max/Team/Enterpriseに提供。開いているファイルの編集、Sheetsの数式修正、Slides編集をサイドバーから実施。組織管理者はMarketplaceアプリをOU/グループ単位で配布でき、標準では編集前承認。別途、Claudeチャット内からGoogleファイルを編集するコネクタもbeta。出典: https://support.claude.com/en/articles/16951679-use-claude-in-google-docs-sheets-and-slides / https://support.claude.com/en/articles/10166901-use-google-workspace-connectors
4. **Compliance API対象拡張（10月8日、beta） [一次情報]** — Claude Enterpriseの既存Compliance Access Keyでunified Claude experienceのchatをCompliance APIから取得可能に。出典: https://platform.claude.com/docs/en/release-notes/overview
5. **SDKのbrowser/computer useクラス（beta） [一次情報]** — Python/TypeScript SDKにブラウザ/デスクトップ操作のtoolset用クラスを追加。独自自動化実装と承認callbackを組み込み、SDK側でtool loopを管理できる。出典: https://platform.claude.com/docs/en/release-notes/overview
6. **Managed Agentsのネットワーク境界を強化 [一次情報]** — `limited` networkingの`allowed_hosts`を`web_search`/`web_fetch`にも適用。許可外のweb_fetchは`url_not_allowed`、web_searchは対象外ホストを除外。allowed_domainsとallowed_hostsの矛盾はsession作成/更新時400。出典: https://platform.claude.com/docs/en/release-notes/overview
7. **Max/Team向け月次API credit [一次情報]** — Max 5xは$100、Max 20xは$200、Teamはユーザー間共有で最大$500/月。Claude PlatformでのAPI実験向け。出典: https://www.anthropic.com/claude-haiku-5-5

## 2. なぜ重要か

**[分析]** 高頻度・低複雑度の分類/抽出をHaiku 5.5へ、複雑な判断や実装をSonnet/Opusへ分離するmodel routingの費用対効果が改善。特にキャッシュ比率が高いagentはSonnet側の価格改定も再試算すべき。Google Workspace編集は実務導入の間口を広げる一方、Workspace管理者・Claude管理者双方のポリシー確認が必要。Compliance APIとManaged Agentsのネットワーク制限は、業務導入で必要な監査・外部接続統制の強化に直結する。

## 3. 具体的なユースケース／シナリオ

**[分析]** 社内案件・問い合わせの一次分類をHaiku 5.5で大量処理し、判断困難な案件だけSonnet/Opusへエスカレーション。Google Sheetsで月次KPI表の数式や異常値を確認し、変更前承認を必須にして試験導入。企業内調査Agentには許可済みホストだけを設定し、外部Webからの意図しない情報取得を制限。Enterprise管理者は新しいchat surfaceの監査取り込みを検証する。

## 4. 技術的な示唆・統合パターン

**[一次情報] Haiku 4.5→5.5は単純なmodel ID置換ではない。** 旧`thinking: {"type":"enabled","budget_tokens":N}`は400エラー。新モデルはadaptive thinkingがデフォルトで、レスポンス先頭が`thinking` blockとなり得る。content blockを位置ではなくtypeで解析する必要がある。tokenizer変更により同じテキストでも概ね30%多いtokenを消費するため、token budgetとコスト見積を再計測。100K token超でHaiku 5.5単価が5倍になることもルーティング条件に反映。出典: https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide

**[分析]** 推奨パターンは `Identity → policy → task router → Haiku/Sonnet/Opus → sandbox & allowed_hosts → tool approval → audit`。既存APIコードの回帰テストにはthinking block、最大出力、料金境界、許可ドメイン、監査ログ欠落を含める。
